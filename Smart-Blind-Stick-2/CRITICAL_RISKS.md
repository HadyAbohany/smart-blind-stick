# Critical Risks and Purchase Gates

| ID / Severity | الدليل والنتيجة | التحقق المطلوب والمرحلة |
|---|---|---|
| R1 / Critical | خطأ الـ part number `Bourns MF-R150`، وF1 مش فصل سريع للتيار ولا يمنع SW5 collapse عند fault. | قبل الـ portable build، اختار SKU مصنعي من datasheet وحماية لفرع الكاميرا. اختبر الحمل والقصر المحاكى بشكل current-limited. Gate C يتطلب 0 missed local cues في 30 محاولة reference أثناء fault injection. |
| R2 / Critical | نفس 5V rail للـ ESP32-CAM وlocal MCU. السحب المتزامن والـ caps يقدروا يعملوا brownout أو cutoff. توصيل 5V header وUSB في نفس الوقت خطر back-feed. | Scope الـ rail عند البوردين أثناء cold start والراديو والموتور. 4.75–5.25V و0 resets. مصدر واحد في كل اختبار. اختبر camera rail independently قبل الدمج. |
| R3 / Critical | المستشعر مجهول. Divider صحيح حسابيًا فقط. Echo clamp/overshoot وpower sequencing ممكن يضروا U1. Timeout بيتعامل كـ clear بعد 3 returns مفقودة. | Scope U2 قبل IO27، سجل VDD والـ ringing تحت الحمل. اختبر open/stuck-high/low بشكل متحكم فيه. قبل حركة بشرية، self-test وسلوك fault واضح للمستخدم. |
| R4 / High | إعلان U1 Type-C DevKitC-style يختلف عن الرسمي. M1 غير محدد وممكن يكون 3V، أو يسحب أكتر من المواصفة. المجس الخارجي غير محمي من ESD. | صور وتوثيق الـ SKU والـ power path أولًا، وموتور 5V qualified. قبل field build حدد حماية ESD منخفضة التسريب للـ JP1/long switch leads وتأهيل الأسلاك والـ enclosure. |
| R5 / High | wet haptic مرحلة حرة من uptime والـ echo wait blocking. الإشارة ممكن تتأخر أكتر من 600ms. الـ ADC raw thresholds افتراض. | 20 دورة start phase عشوائية لكل مادة وقياس contact→motor. ≥18/20 tap water ≤600ms؛ لو فشل نبدأ pattern عند الانتقال ونعيد قياس نفس العينة. |
| R6 / High | Android وESP32-CAM الأجهزة مش متأكدة. PSRAM، frame age والـ 2.4GHz coex غير مقاسين. `setTimeout(500)` في الكاميرا مش deadline للـ send. | Benchmarks A/B، وBLE freshness/reconnect مع camera/AP loss. احتفظ بـ no-internet local route واعمل test لشريحة حقيقية. شراء العينة بعد A والدوائر. |
| R7 / Critical للـ live SOS | SEND_SMS hard-restricted، app foreground مقيدة، snapshot آخر event فقط، late tick بعد resume، ونتيجة SMS لآخر مستلم بس. | ركّز على مسودة في Phase 1. قبل auto send لازم allowlist/grant، فرق sent/received لكل contact، حماية حالة cancel/expiry، وتعامل مع فقد الاتصال وprocess death. اختبار 0 رسائل mock/cancel وتأكيد هرمي من المستلم. |
| R8 / High | Accel+gyro mock لا يثبت كشف سقوط. التوقف في `onPause` يقفل sensing مع lock/background، وحركة الهاتف غير مماثلة لحركة الشخص. | jig/recorded fixtures ووضع الهاتف على الجسم. لو مطلوب screen off، implement session/service واختبر OEM/Doze مع notification cancel. NO-GO لاستخدام fall كنظام إنقاذ لحد validation. |
| R9 / High | الكود بيتحقق من وصول GATT read، وsequence ثابت برضه بتحدّث freshness. أول device بنفس service بيتاخد. Camera cue يتأثر بـ TTS، ولا تتأكد حالة النظام من audio output. | under radio load اتبع bootId/seq، غيّر stick أو link واعمل fault cases، وافحص TalkBack/engine discovery وforeign pairing. اسمح بالـ contextual speech بس لما link حديث ومؤكد. |
| R10 / High | صور benchmark مش موجودة، والـ model output contract غير مجرّب. الـ pipeline عند 180ms nominal يسيب هامش صغير عن 5 FPS. | سجل SHA256 وتوافق output، قياس sustained FPS مع thermal وp95 حقيقيين. لو فشل، أعد التجربة مع model backend أو settings على نفس الـ phone واترك الـ camera tier معلّق. |

الـ Critical gate في الاختبار المعملي يسمح بتجربة controlled لكشف المشكلة. Fail في safety أو emergency لازم يتقفل قبل اعتماد شراء النسخة الكاملة أو demo يعتمد على الوظيفة المتأثرة. تفاصيل المصدر والداتا شيت في [Engineering Audit](ENGINEERING_AUDIT.md).
